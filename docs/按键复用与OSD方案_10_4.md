# 按键复用与OSD方案

日期：2026-10-04。本文区分Jeremy已采用的操作方案和当前已实现功能。

**2026-10-05 更新：下文为实施前历史记录。已按后续确认的 96 行底栏、黄色黑边准心、2/10 像素步进和 1/2/4 倍方案，在 ScalingTest 分支完成 RTL 接入和软件构建。当前操作、实现与验证边界以 [ScalingTest说明](ScalingTest使用与实现.md) 和 [验证报告](../reports/ScalingTest验证报告.md) 为准；已于 2026-10-05 完成上板验收（第 0~5 步通过、第 6 步跳过）。**

## 已采用的四开关、四按键方案

Jeremy明确回复“上面这个按键方案我采取了”，采用以下分配：

| 操作 | 开关条件 | 功能 |
|---|---|---|
| SW1、SW2 | 00／01／10／11 | 原图／Sobel边缘／灰度／二值化，保持已有分配 |
| KEY1 | 无 | 复位 |
| 按住KEY2 | SW3=1／0 | 增大／减小摄像头增益，调亮／调暗 |
| 按住KEY3 | SW3、SW4=00／01／10／11 | 观察位置向下／右／左／上移动，SW3为高位 |
| 按住KEY4 | SW4=1／0 | 放大／缩小 |

采用上一轮方案的防误操作规则：KEY1复位优先；KEY2～KEY4同时按下时暂停调节，只剩一个键时再响应；有效单键操作开始时锁定消抖后的开关组合，本次持续按住时不随开关改变方向。松开重按后采用新组合。具体消抖时间、连发速度、倍率档位及边界处理仍需实现时明确。

SW1/SW2已实测上0下1；SW3/SW4方向尚需上板确认，不照搬手册相反的方向描述。

板卡手册《新HX1P35A开发板手册-HDL版2604》第21～23页：SW1=A4、SW2=B4、SW3=E11、SW4=D11；KEY1=D5、KEY2=A9、KEY3=B9、KEY4=C7。SW5为蜂鸣器开关，SW6选择双色LED或数码管工作，不能直接作为本方案的通用输入。

## 当前代码与新方案的差别

当前仅接入SW1/SW2及KEY1/KEY2/KEY3。`camera_capture.v`的`.I_btn({I_button,2'b11})`把KEY2/3接到`ae_set.v`的增益减／增分支，曝光时间控制输入固定为未按下。因此历史文档中的“KEY2/3曝光调节”是泛称，准确表述为“摄像头增益调节”。新方案实施时须移除KEY3原增益增加功能，避免移动时同时变亮。

本次仅确认并记录分配，**未修改RTL、引脚约束或bit文件**。准心移动、缩放、复用控制都尚未实现；颜色环及自动跟踪方案仍未确定。

## OSD要求的解释与核查

根据Jeremy提供的要求，OSD即在实时输出视频上额外叠加图形或文字。例如十字准心、观察区域框、模式名称、倍率、官方Logo；其中要求必须包含安路标识。

当前`rtl/09_osd_ui/`只有README，TD工程未加入该模块；`memory_video_out.v`中`image_preprocess`的RGB及同步输出直接送入`hdmi_tx`。`hdmi_mixer.v`的调试彩条／状态色块用于替换诊断画面，不构成已完成的安路Logo叠加。因此本项要求目前**未完成**，计划中的准心也未实现。

官方Logo已保存于[assets/osd/anlogic](../assets/osd/anlogic/README.md)。素材已检查可解析并渲染预览，不等于已经显示到HDMI；本轮没有编译或板上验证。

后续布局建议为角落保留安路Logo、观察区显示准心，并视需要增加模式和倍率文字。这是建议，尚未定稿；本轮未开始OSD硬件实现。
