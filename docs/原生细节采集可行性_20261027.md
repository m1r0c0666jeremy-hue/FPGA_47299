# 原生细节采集可行性

日期：2026-10-27。目标：放大观察时获得更多实际采样细节，继续用1倍原图坐标定义矩形、定位和示教，最终保留1280×720输出及624行视频＋96行底栏。

**结论：可以参考已有独立1080p30候选研究更密的原生采集，但当前区域／示教工程尚未完成这项整合。相机支持原生高清不等于已经支持按五档倍率动态移动采集窗口，也不能保证3／4倍画面仍有1280个独立横向像素。** 本文件记录已查事实、推导和验证边界，不作为新bit通过证明。

## 1. 当前720p链路究竟做了什么

当前SC500CS输出1280×720；采集、ISP、完整RGB帧缓存和检测都按这个尺寸运行。检测没有先缩成320×180。相机内部使用2×2合并与裁剪，FPGA接收到的是合并后的720p图像。

输出HDMI也是1280×720。其中上624行视频，后96行底栏。原图仍有720行坐标，可通过视口跟随查看未同时显示的上下部分。

现有倍率的源窗口如下；窗口经过最近邻取样扩展到1280×624显示。

|倍率|本次显示使用的原图窗口|含义|
|---|---|---|
|1×|1280×624|原尺寸视频窗口|
|1.5×|853×416|较小窗口扩展显示|
|2×|640×312|横纵每个源像素约占两个显示像素|
|3×|427×208|较小窗口扩展显示|
|4×|320×156|横纵每个源像素约占四个显示像素|

因此放大后HDMI分辨率并没有下降；下降的是当前画面对应的独立源像素数量。换一种插值可以使边缘平滑，但不能恢复没有采到的细节。

依据：本工程`user_source/hdl_source/uics500_cfg/uics500reg_720p60.v`、`rtl/color_regions/stable_camera_capture.v`、`stable_capture.v`、`stable_line_reader.v`及`refined_zoom_geometry.v`。本文件没有改动这些模块。

## 4. 真正细节提升的上限

下面是基于当前2×2合并模式、原生像素数量和相同镜头／物距的推导，尚不是实物测量结论。

原720p一行1280个合并后像素，对应约2560个原生横向采样位置。若2倍窗口对应原图640像素宽，那么取消合并后可获得约1280个真实横向像素，接近“2倍观察仍有1280个真实横向像素”的目标。

同样推导，3倍窗口约能得到854个、4倍约640个原生横向像素。继续铺满1280宽显示时仍须扩展。若要相同1倍视野的4倍裁剪仍含1280个真实横向像素，等效全视野需要至少5120个横向采样位置，超过本传感器约2600的宽度。

所以约2倍是这套传感器和原视野关系下的合理原生细节目标。3／4倍仍可以比当前合并图的纯数字放大更清楚，但不能称为“每档都获得完整真720p细节”。镜头分辨率、对焦、光照和透明色环的形态也会影响收益；像素数增加不保证尖端误差按比例下降。

已有1080p工程预计覆盖旧720p视野约75%的宽、高，且同一物体线性像素约增加一倍；原寄存器窗口尺寸也支持这一推导。实际有效区域原点、裁剪边界和颜色排列仍须用图卡校验，不能直接把寄存器窗口起点当作已校准的1倍坐标偏移。

## 5. 可比较的技术路径

|路径|潜在收益|主要限制|本阶段选择|
|---|---|---|---|
|维持当前720p采集，只改插值|显示边缘可能较平滑|没有新的真实细节|不能满足本次原生细节目标|
|固定原生1080p采集，映射并输出720p|有现成候选可参考，可先验证真实细节与坐标对应|视野比旧1倍小，帧率、DDR、检测及缩放需重新联接；单个固定窗口不能覆盖旧全视野|作为独立可行性验证入口|
|传感器动态原生ROI，保持720p输出|可能减少高清全帧存储，并跟随目标读取更密的局部图像|缺完整热切换规则；移动窗口可能丢失A/B之一；帧身份、颜色排列、恢复和边界均需验证|先调查／验证，不承诺整机功能|
|原生全视野高清采集再裁剪|更容易保留统一全局视野和坐标，避免移动传感器窗口|带宽、内存、检测计算量与帧率代价较大；现有40个DSP已满|资源评估后再决定|
|光学放大或更高分辨率相机|可能进一步增加真实细节|涉及硬件、视野和标定变化|本轮软件修改范围外|

独立验证优先复用已有固定1080p采集经验，并保留720p区域／示教候选。固定1080p成功后再依据实际资源和画质决定是否推进动态ROI；不能把动态切换作为已经可交付的默认能力。

## 6. 坐标与显示怎样保持一致

后续整合以旧1倍1280×720原图作为统一坐标系。高分辨率检测位置先通过已校验的比例与裁剪偏移映射到这套坐标，再供准心、矩形、示教和顺序判断使用。只改变当前观察窗口，不把旧区域坐标乘以倍率重新保存。

显示则用同一个坐标变换，把当前图像、区域框、尖端和回放位置映射到1280×624视频区；后96行继续显示OSD。旋转方向、边界裁剪和视口跟随都必须参与同一份帧快照。传感器窗口改变时，要更新配置身份并等待新完整图像，禁止把旧窗口的元数据贴到新窗口图像上。

保持1倍坐标系不代表自动增加坐标小数精度。当前尖端和路线使用整数原图坐标；更密采样可能使检测更稳定，但若仍保持这个接口，最终结果仍按原图整数格表示。不能在没有修改坐标格式和验证的情况下宣称获得任意亚像素定位精度。

原生ROI必须同时包含被跟踪的A、B标记，否则现有双色定位失去依据。仅使尖端处于小窗口中央，不足以保证工具仍可检测。已有区域和回放点处于采集窗口外时，应明确画外状态，不可伪造检测结果。

## 7. 独立验证顺序和实物表

先核对固定原生模式的完整帧尺寸、真实帧率和同一位置的细节，再用参考图卡测量旧1倍坐标到新图像的比例／偏移。之后才评估720p读出、624＋96布局和区域／示教统一映射。动态ROI需要单独的切换／恢复验证；未完成时不接入正式功能。

新整合必须使用独立输入快照和构建目录。继承旧候选“通过”的结论只能用于指出可参考实现，不能代替新源码的软件、资源、最终布线和时序检查。任何新bit在Jeremy上板验收前仍标候选。
