# ScalingTest 使用与实现

日期：2026-10-05。基于 `main e671630` 的独立分支，平台 HX1P35A / PH1P35MDG324 −3，TD 6.2.168116。已于 2026-10-05 完成首次上板验收（第 0~5 步通过、第 6 步跳过），逐项结果见验证报告。

## 操作

| 操作 | 效果 |
|---|---|
| SW1/SW2=00、01、10、11 | 原图、边缘、灰度、二值化；保持原映射 |
| KEY1 | 复位至原图坐标(640,360)、1倍、增益90；模式跟随稳定SW1/SW2 |
| KEY2 + SW3=1 / 0 | 摄像头增益增加 / 减少，不调整曝光时间 |
| KEY3 + SW3/SW4=00 / 01 / 10 / 11 | 下 / 右 / 左 / 上移动 |
| KEY4 + SW4=1 / 0 | 放大 / 缩小，倍率档位1、2、4 |

KEY2/3/4 为低电平按下。SW1=A4、SW2=B4；SW3=E11、SW4=D11；KEY1=D5、KEY2=A9、KEY3=B9、KEY4=C7。SW1/2 已实测上0下1；**SW3/4 亦已实测上0下1**：上上=00→下、上下=01→右、下上=10→左、下下=11→上，全部与设计电平一致。SW5/6 不接入本功能。

按键和开关约20ms消抖，稳定后立即执行一次。KEY3 首次2个原图像素，按住400ms后每80ms再移动2像素；按住1秒后每80ms移动10像素。KEY4 每600ms重复一档；KEY2 每150ms一档，范围16～105，默认90，曝光固定1990。步进为原图单位，因此4倍显示时2个原图像素对应8个屏幕像素。

KEY1 优先。KEY2～4 同时按下时暂停，显示“按键冲突”；恢复单键后作为新一次操作。每次操作开始锁定SW3/SW4，按住中途拨动不改变本次方向；KEY3松开时显示当前开关方向。复位后等所有键释放并稳定，再接受操作。松手、冲突等也经过消抖，因此有约20ms确认时间；状态在下一显示帧更新。

## 画面与坐标

输出1280×720；视频区为上方624行，底部96行深色栏覆盖视频，不压扁图像。两行文字起点(16,636)、(16,680)，24像素字符单元。左侧显示模式、原图坐标、倍率、KEY3方向和状态；右侧白底区域显示官方图形和“安路科技”。状态为待命、移动、到边界、按键冲突；新读出链路欠载时优先显示“视频未就绪”。

坐标原点在原始1280×720图像左上角，X向右、Y向下。复位取第48～671行，准心在(640,312)。1倍时先移动准心，距上下可见边缘小于32像素时平移，垂直起点限制0～96，能选到原图第719行。2倍取640×312，4倍取320×156，以选点为中心并限于源图；边缘处准心偏离屏幕中心。缩回1倍保留选点，使其可见。

准心黄色、黑色描边，外接27×27屏幕像素，中间留空。所有倍率下尺寸固定，画到四边时裁剪，不进入底栏。整数放大时准心放在选中源像素重复块的中间像素，偶数块取靠右/下的一个像素。坐标、窗口、倍率、方向和状态在VS上升沿提交；缩放器稍后锁定窗口，OSD使用已生效参数。四模式自身也在VS锁定，OSD读其实际模式。

## 链路与缓存

`摄像头/ISP → 原DDR写入 → scaling_line_reader → image_preprocess → scaling_osd → hdmi_tx`

新增 `scaling_controls.v` 负责按键，`scaling_viewport.v` 负责窗口换算和帧提交；`camera_gain_control.v` 替代当前路径中的 `ae_set`，通过请求/应答传递增益命令。方向在源端保持到应答，接收端两级方向同步、三级请求同步，应答两级返回；摄像头配置完成后按原接口发起I2C更新。旧 `ae_set.v` 保留，KEY3不再连增益增加。

新缩放器每源图行发出240个128位读取事务，地址每拍加8，行跨度1920。四缓存基址为0、7000000、14000000、21000000。连续三字拼成384位，按厂家大端RGB字节顺序组成16像素，避免跨128位字和行尾数据丢失。两组完整行缓存各80组、有效宽度1280×24；采用384位宽、256深RAM的两半，未使用地址由有效标记屏蔽。没有全帧片上缓存。

像素侧维护每个行缓存的源行号及有效位，通过保持数据的请求/应答传递行号、目标缓存和新帧标记。DDR侧每帧首行锁定读缓存基址，一帧内不跟随写侧更新的读指针。消费完一源行的最后一次纵向重复后才释放该缓存；横向通过重复读取像素实现最近邻放大。预取仍读完整源图行，因而无需在DDR上处理非16像素对齐的横向窗口。

读写共用命令接口。等写所有权释放后预留下一次读机会，等待已寄存的最后一拍写使能结束，再发读突发；240个读命令发完后可让写入继续，同时排空读响应。相机采集保持原节奏，无新增反压。测试使用持续请求写突发的最不利等待条件，检查读写不重叠和读出不饥饿。

缺少所需行时，本帧剩余视频置黑并保留OSD，不把晚到数据误用于新行。跨帧旧请求带代号，不接纳旧响应；旧请求排空后等待下一帧重新读。延迟超过一帧时，恢复可能需要多于一帧。若DDR永不返回已发请求，则不能自行恢复；本轮不重置DDR协议或修复整个旧采集链路。默认也未验证任意相机帧率/坏帧下旧四缓冲管理的完整性。

四模式算法在缩放后处理，2/4倍边缘是“放大后检测边缘”；保留原Sobel相对窗口中心右下约1像素偏移。显示侧缩放2级、处理5级、OSD2级，同步与RGB共9级寄存（采样沿计入第1级，输出在第9级更新）；完整时序仿真对此逐拍比较。
