# 原生2倍细节与三档倍率候选

当前在 `Final_Mode_1028` 整合验证；本说明不是整机通过或实物通过记录。新工程：`td_project/target_color_regions_native_zoom.al`。原用户工程 `target_color_regions_stage1.al` 不改写。没有推送、下载到板或写Flash。

## 采集与显示

采用 SC500CS 2592×1944 RAW10 双通道原生模式，传感器参考时钟24MHz，处理60MHz；原HDMI像素/串行时钟、1280×720输出和624行视频＋96行底栏保持。相机约30fps，显示约60Hz，重复显示完整帧不产生新的检测观察。

寄存器取自 Ulefone 公开驱动固定提交 `de34198b04c5dc11b23c16ffcd121ce978c7bc1e` 的87项有效初始化写入，追加同一驱动preview的 `0100=01`，共88项。来源、完整文件SHA256和序列保存于 `vendor_reference/sc500cs_native_2592.json`。没有混用1080p模式的PLL与读出寄存器。参考：[厂商驱动](https://github.com/ulefoneofficial/Power-Armor-13/blob/de34198b04c5dc11b23c16ffcd121ce978c7bc1e/kernel-4.14/drivers/misc/mediatek/imgsensor/src/common/v1/sc500cs_mipi_raw/sc500csmipi_Sensor.c)；大赛SC500CS V1.8手册。

原生ISP全幅处理后，RGB在初值(16,252)裁出2560×1440；图卡校正集中修改 `rtl/color_regions/native_zoom_config.json` 的crop_x/crop_y后重新生成、验证及构建。支持整数原点，包括跨四像素组的裁剪；Bayer处理在裁剪前完成。初始视野对应关系尚待Jeremy图卡实测。

每帧高清RGB888实际写691200个128位字，四帧有效数据42.1875MiB，银行地址仍为0/7000000/14000000/21000000（每地址16位）。完整原生帧尺寸、实际包长度、原始结束信号、全幅ISP数量、全部高清写入及相同身份的检测结果共同决定可显示状态。裁剪区外坏行也会撤销该帧。平台原CSI解析器不提供CRC/ECC解码，本版新增尺寸/包终止检查，不能据此声称已校验传输中的全部位错误。

保留1×、1.5×、2×，普通倍率键循环三档；K及亮度操作保持此前实物确认版本。1×/1.5×使用高清图每通道2×2平均后的1280×720流；校准平均在增益前，检测平均在增益后。平均只在最终除4时舍入。2×读取1280×624个真实高清像素，对应旧坐标640×312窗口，不重复旧720p像素制造细节。坐标、矩形和路线仍用旧1倍整数坐标；倍率切换不重配相机。

高清读取使用两块轮换暂存区，使DDR读入和缩小同时进行。写突发末拍也阻止读命令，以保护共用地址端口。读取缓存不会把整幅高清图搬进片内存储。

核查发现旧视频模块把50MHz板载时钟直接送给参数为100MHz的DDR IP，因此原用户时钟实际66.667MHz。新高清读取的计算吞吐不能在该频率持续满足约60Hz显示。本版新增独立DDR参考输入，连接原PLL的100MHz，使DDR用户端恢复配置要求的133.333MHz、物理速率约1066MT/s；原50MHz恢复计时/遥测仍保持。SDC由真实连接推导时钟，不用放宽约束伪造通过。该DDR速率变化和新相机模式一样，均需新整机物理验证与Jeremy实物确认。
