# 原生1080p30摄像、识别与显示升级规范

状态：用户于2026-10-24确认测试边界、四张工单及依赖；已发布到本地工单系统。标签：ready-for-agent。

## Problem Statement

现有英文版系统以720p完成摄像、处理和显示。用户希望在现有硬件上尝试原生1080p，提高中央目标可观察的细节，同时保留已有识别、校准、跟随、缩放和显示功能，并继续满足大赛对稳定采集、实时处理和安路标识叠加的要求。

## Solution

提供独立的原生1920×1080、标称约30fps候选工程。用户接受厂家FHD中央裁剪带来的较窄视野，继续使用原工具、色环、镜头和物距。保持原有操作规则，完成软件验证、实际资源和最终时序检查后才交付可下载候选；由用户或队友进行SRAM实测，确认后再考虑替换比赛版本。

## Implementation Decisions

- 保留现有PH1P35板卡和SC500CS摄像头；使用厂家完整1080p30设置，不拼接不同模式的模拟或读出参数。
- 接受FHD中央裁剪。原工具尺寸类阈值以线性×2、面积及距离平方×4为迁移初值；画幅比例及界面布局单独适配。实际视野、帧率和画质需上板验证。
- 接收及CSI/RAW10解包使用恢复时钟；经1024深整行准入异步桥进入60MHz处理域。每行校验480组四像素数据和真实行尾后连续回放，行间留96拍。
- 帧身份、原始采集时间与数据一并传递。错误通知使用Gray事件计数，允许处理时钟停止期间累计多次错误；异常帧不得被标记为完整可读。
- 系统PLL从50MHz生成100/24/60MHz。HDMI PLL级联60MHz参考，采用整数99/4反馈和20/4输出分频，获得74.25/371.25MHz；避开当前工具对小数反馈编码的解释差异。
- HDMI使用2200×1125总时序、正同步及1080p30模式。微秒计时、按键消抖和操作定时适配新的像素时钟。
- RGB888每帧388800个128位字，每行360字；保留四帧银行和240字写批次，在实际写事务完成后才发布完整帧。
- 三块ISP行存储缩为512深，扩大显示侧行缓存；所有Y坐标和完整帧计数均覆盖1080p范围。
- 检测处理全部原生像素；80×45粗网格采用24×24像素单元，保持候选数量和颜色算法，不增加DSP通道。
- 材料/白纸校准框32×32，均匀选取每帧256像素；中央背景16×16内选取64像素，配合全场192像素维持256负样本。每步仍为八帧、2048样本。
- 元数据版本升级为v5，集中定义扩展坐标及计数字段，保持主要候选、结果和快照总线容量。
- 底栏96行，视频区域1920×984；保留两配色、四模式、五倍率、旋转、尖端公式及三帧/15帧/八帧规则。
- 所有新工作在独立副本完成；最终候选必须通过输入一致性、软件验证、资源和最终建立/保持时序门槛。

## Testing Decisions

- 测试独立定义的外部行为和字节/像素期望值；不得通过读取内部RAM、私有状态或重复实现算法来证明外部功能正确。既有深层检查保留为诊断证据，不追称为新增TDD。
- 已确认边界A：摄像头数据包、用户操作及复位输入，到输出视频像素、同步和OSD的观察边界。使用真实自有模块与可仿真的厂家逻辑，仅在物理传感器、PHY和外部存储电气边界建模。覆盖帧完整性、同帧识别、缩放、旋转、校准和恢复；不证明光学清晰度、板级电气或实际传感器帧率。
- 已确认边界B：冻结源输入和构建命令，到候选交付或明确拒绝的CLI边界。覆盖源码对应、资源/时序门槛及失败不误发布；不证明板上运行质量。
- 沿用原英文工程已有完整视频、实际FIFO、帧银行、真实CSI解包和I2C联接验证思路，新增或修复时按单个行为进行先红后绿。
- 对单项修改运行相关测试和RTL展开/编译检查；最终对当前候选统一执行约定的回归套件，并检查每项记录与当前源码的哈希对应。
- 实物阶段由用户或队友检查标准显示模式、真实采集帧率、对焦与4倍细节、全部操作、异常恢复和30分钟连续运行，单独记录结果。

## Out of Scope

- 真实1080p60采集、强制保留720p的全部视野、更换硬件、识别分支降采样及删除现有功能。
- 额外加入锐化、插值、全新识别算法或放宽现有颜色学习条件。
- 自动下载板卡、烧写Flash、覆盖旧交付、修改原工程或把未通过最终时序的bit标记为可用。
- 在没有实物证据时保证清晰度提升、识别率、实际采集帧率或长期稳定性。
