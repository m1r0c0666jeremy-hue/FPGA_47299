# 720p 回退与源图坐标不随倍率变化

状态：用户于 2026-10-25 确认功能、测试边界 A/B、两张工单和依赖、复用已审计 bit 的交付方式。标签：ready-for-agent。

## Problem Statement

现场显示器的 EDID 未声明 1080p30，且声明的垂直刷新率下限为 48Hz，现有 1080p30 候选出现"超频"。用户要求恢复原 720p 版本，保留局部放大，并保持原 1 倍图像的坐标体系。

## Solution

恢复原英文 720p 工程的摄像头采集、识别、缓存、显示和按键操作。五档局部放大均在 1280×720 的源图上取样，HDMI 输出仍为 1280×720。目标、色块框和尖端的结果坐标始终属于源图；缩放、移动视窗和显示旋转只改变图像与标注在屏幕上的位置。例如同一输入目标的源坐标为 (640,360)，五档倍率下结果均为 (640,360)。

## User Stories

1. As a 现场使用者, I want 恢复原 720p 采集, so that 使用原来的摄像头模式和视野。
2. As a 现场使用者, I want HDMI 恢复 1280×720 输出, so that 可以验证现场屏幕能否正常显示。
3. As a 使用者, I want 保留 1× 显示, so that 可以观察基础画面。
4. As a 使用者, I want 保留 1.5×、2×、3×、4×, so that 可以继续查看局部细节。
5. As a 使用者, I want 放大后输出仍为 720p, so that 倍率切换不改变显示模式。
6. As a 算法调用方, I want X 坐标固定属于 0～1279 的源图坐标, so that 不需要随倍率换算。
7. As a 算法调用方, I want Y 坐标固定属于 0～719 的源图坐标, so that 不会混入视频区或底栏坐标。
8. As a 使用者, I want 同一帧同一目标的结果不随倍率变化, so that 放大只影响观察方式。
9. As a 使用者, I want 色块框随视频正确放大和裁剪, so that 标注始终覆盖对应目标。
10. As a 使用者, I want 尖端标记随视频正确映射, so that 放大后仍能找到尖端。
11. As a 使用者, I want 保留 0°/180° 显示, so that 沿用现有安装方式。
12. As a 算法调用方, I want 显示旋转不改变源图结果的坐标定义, so that 结果含义保持一致。
13. As a 使用者, I want 保留原来的自动跟随, so that 放大视窗可以继续跟随目标。
14. As a 使用者, I want 视窗靠近图像边缘时正确限位, so that 不读取源图范围之外的数据。
15. As a 使用者, I want 保留四种图像模式和两套配色, so that 原有操作继续可用。
16. As a 使用者, I want 保留校准、英文底栏和安路 Logo, so that 回退后功能完整。
17. As a 使用者, I want 倍率在帧边界生效, so that 一帧中的视频和框线保持一致。
18. As a 使用者, I want 丢失目标或无有效帧时保持原失效处理, so that 不把过期坐标当成当前目标。
19. As a 队友, I want 获得来源明确的 SRAM bit、源码和哈希, so that 可以复现和记录上板结果。
20. As a 队友, I want 软件和物理构建结果与实物验收分别记录, so that 可以知道哪些项目仍待现场验证。

## Implementation Decisions

- 优先恢复已审计的英文 720p 基线，采用其 1280×720 源图、1280×624 视频区和 96 行底栏。1× 默认视窗原点为 (0,48)，目标结果仍使用完整源图坐标。
- 保留原五档最近邻取样、按键、校准、跟随和旋转行为。局部放大属于显示取样，不改变源图的识别分辨率。
- 原英文基线的实际 HDMI 像素时钟为 75MHz，串行时钟为 375MHz，总周期为 1650×750，理论刷新率约 60.606Hz；本次建议严格恢复原配置，不能把它记录为精确 60.000Hz 或已验证的标准时序。
- 每个倍率的源视窗宽高沿用原基线：1280×624、853×416、640×312、427×208、320×156。
- 识别结果的源坐标与显示框、尖端的屏幕映射分离；不能把缩放后的屏幕位置写回识别元数据。
- 不新增数值坐标显示、UART 或其他外部协议。对现有结果接口验证坐标含义；需要新增显示或通信属于另一个需求。
- 恢复 720p 的阈值、计数宽度、行缓存、帧长度、相机表和显示时序，防止混入 FHD 专用常量。
- 使用独立的 720p 工作副本进行恢复和提交；实际交付必须记录源版本和输入哈希。
- 已核对原 720p 工程全部 297 项编译输入与冻结英文基线一致，源坐标行为已存在。如果交付源码的编译输入与该已通过物理门槛的候选完全一致，优先复用其 bit 并明确记录旧构建来源；不得称为新构建。若编译输入有变化，必须重新完整构建并通过资源和建立/保持时序门槛。
- 对不需要修复的已有行为保留现状，不为制造失败测试而修改正确实现。

## Testing Decisions

- 已确认边界 A：摄像头帧输入、用户控制和复位，到实际 HDMI 像素/同步/标注及现有同帧结果输出。验证五倍率下目标结果源坐标一致、显示映射正确、帧身份一致。视窗中心可以随跟随和限位变化，不能把视窗中心误当成目标源坐标。优先沿用现有实际模块联合视频与独立像素参考。
- A 能发现源坐标被缩放、框线错位、边缘越界、帧内切换或混用旧结果；不能验证真实镜头成像、MIPI 电气、DDR 电气或屏幕实际兼容性。
- 已确认边界 B：公开构建/打包入口输入，到带来源信息的候选交付或明确拒绝。核对 720p 依赖、资源、建立/保持时序和源码/bit 对应关系。
- B 能发现工程引用混用、过期交付和构建门槛遗漏；不能替代上板实测。
- 测试只断言可观察行为，期望来自规格、独立参考和已审计基线，不依赖内部寄存器实现或复写被测算法。
- 在用户确认边界后按 TDD 逐片推进：一个失败行为、最小实现、通过后再进入下一片。已有正确行为直接执行回归，不伪造失败。

## Out of Scope

- 1080p 采集或输出、2592×1944 Full 配置、1080p30→1080p60 帧重复。
- 新的插值、锐化、压缩、判色算法、通信协议或数值坐标界面。
- 将原约 60.606Hz 的时钟重新设计为精确 60Hz。
- 自动下载板卡、烧写 Flash、远程发布或代替现场进行硬件验收。
