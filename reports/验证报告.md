## 已复现及未覆盖的问题

1. `data_96bit_to_128bit` 没有使用复位输入；有效数据中复位不会清除打包组。测试以 `KNOWN_LIMITATION pack` 明确记录。无效拍清分组计数，因而任意行内间断也不能保证字节连续。
2. `video_in` 没使用FIFO满标志，满时摄像头仍写，没有可验证的丢帧/溢出恢复机制。摄像头不能被随意反压。
3. `video_out` 虽接出空标志但未用于读控制，空时仍读，没有可验证的黑场/欠载恢复机制。
4. 缓冲指针在帧开始附近轮换，没有完整帧有效提交协议；异常帧、启机未填充、输入/输出速率差下的安全帧选择尚无保证。MIPI错误输入沿用例程常量0。
5. PLL lock作为逻辑复位，跨域释放未专项闭环；板级复位恢复、热插拔、长时间运行和摄像头实际fps都未测。

上述1～3的测试成功是"发现并稳定复现问题"，不是异常恢复通过。本次按复现基线范围保留厂家实现；后续板上验收前应评估并修复错误帧隔离、缓存满空处理与复位策略，再做回归。未把缺陷隐藏在替代模型中，也未声称现在已能稳定实时显示。

## 2026-10-04 更新二：SC500 曝光/增益通路核对与首次提亮

### 上板实测（用户现场）
- `DEBUG_MODE=1` 彩条按预期显示：8 条（红/绿/蓝/黄/青/品红/白，各 128 px）+ 右侧深灰 384 px，**无任何叠加层**
  → 引脚、HDMI 时序、显示器锁定、bit 下载全部正常（"安路/CNT"字样消失 = 我们的设计在跑）。
- `DEBUG_MODE=0` 摄像头出图 → MIPI RX → CSI/RAW10 → ISP → 96→128 打包 → FIFO → DDR → 读回 → HDMI **全链路通**。
- **按住 KEY2 画面明显变暗** → `ae_set.v` → `uics500regAE.v` 的曝光寄存器写入通路正常。
- 中偏右上"安路 CNT"残留 = 上电时 flash 工厂 demo 写入 DDR 的残影；**掉电后消失**，已确认（非信号问题）。

### 代码核对结论
- `ae_set.v` **不是闭环自动曝光**，而是按键手动曝光/增益；上电时 `r_ae == r_ae_set`、`r_ag == r_ag_set`
  → **不会主动写任何 AE 寄存器**，亮度完全由配置表决定。
- 默认曝光 1990（半行单位 ≈ 995 行）已贴近 VTS=1000 的合法上限；默认增益 AG=80 → `SC500GainTbl(80-16=64)` = **0x0F20 = 4.000x**（原表最大仅到 0x0F3F）。
- 按键映射 `I_btn = {I_button, 2'b11}`：**KEY2(A9)=减曝光、KEY3(B9)=加曝光**；增益两位硬接 1，**按键无法改增益**。
- 数据手册 SC500CS V1.8 表 2-4：**0x1F20 = 8.000x（18.06 dB）… 0x1F3F = 15.75x**；特性页：16x 模拟增益、32x 数字增益。
  手册 2.2.3 要求 **0x3e03[3:0] = 4'hb** 才启用该 AGC 控制寄存器组，而厂家配置表从未写过 0x3e03。
