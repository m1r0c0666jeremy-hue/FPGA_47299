# 原生 1080p30 候选工程

在独立副本中将 SC500CS 采集、原生识别、DDR 缓存及 HDMI 升级为 1920×1080，保留原有功能。原 720p 工程和旧交付物未覆盖。

**状态：软件回归、资源及最终路由时序通过，SRAM实测候选已生成；实物未验收。** 最终交付位置及实测状态以 `reports/fhd/delivery.json` 为准；源码包根目录的 `CANDIDATE.json` 记录该包对应的候选。

最终资源为18791 Slice、99 ERAM、40 DSP；建立+0.118ns、保持+0.020ns。16组最终回归全部通过，详见 [最终验证](reports/fhd/validation.md)。

工程入口：`td_project/target_color_regions_1080p30.al`，顶层 `criticalwork_top`，目标 PH1P35MDG324，TD 6.2.168116。

## 本次行为

- 真实 1920×1080 摄像及处理，厂家 FHD 模式标称约 30fps；HDMI 使用 2200×1125、74.25MHz、VIC34 的 1080p30 时序。
- 恢复时钟域完成 CSI/RAW10 解包，整行校验后经异步桥进入 60MHz ISP/识别域。系统输出 100/24/60MHz，HDMI PLL 使用 60MHz 级联参考的整数分频。
- 每帧 388800 个 128 位 RGB 字，保留四帧银行、实际写完成准入、帧身份和原始时间戳。
- 全部原生像素参与识别；保留两配色、四模式、五档倍率、0°/180°、跟随、英文 OSD 和安路 Logo。
- HDMI 总画面为 1920×1080，其中视频区 1920×984，底栏 96 行；1×初始视窗位于源图中央。
- 材料/白纸框 32×32，每帧均匀采 256 像素；负样本为中央 16×16 内 64 像素及全场 192 像素。每步八帧，仍为 2048 样本。
- 三帧确认、15帧身份期限、八帧校准保持；约对应 100ms、500ms、267ms，操作和算法计算时间另计。

FHD 是非合并像素的中央裁剪，预计覆盖旧 720p 视野约 75% 的宽、高。同物距下物体的线性像素数预计约为原来的两倍，因此尺寸阈值按 ×2、面积与距离平方按 ×4 迁移。实际帧率、视野、对焦和识别效果须上板测量；4×细节收益是对比目标。

## 操作保持

| 操作 | 行为 |
|---|---|
| KEY1 | 全局复位 |
| KEY2 | 按 SW4 方向调整相机增益；校准中取消 |
| KEY3 短按松手 | 启停检测/跟随；校准中采样 |
| KEY3 长按约1秒 | 显隐视频标注 |
| KEY4 | 按 SW4 增减倍率：1×、1.5×、2×、3×、4× |
| KEY2+KEY4 长按约1秒 | 停止跟踪时进入四步校准 |
| KEY3+KEY4 长按约1秒 | 切换0°/180°，默认180° |
| SW3 | 0红A/蓝B，1黄A/紫B |
| SW4 | 1增加增益/倍率，0减少 |
| SW1、SW2 | 00原图，01目标高亮，10灰度，11二值图 |

沿用原板实测开关极性：上=0、下=1。组合键应近乎同时按下，所有键松开后再开始下一手势。KEY2+KEY3 的旧诊断分页已由原英文基线取消，本次沿用。

## 验证和复现

`scripts/generate_fhd.py --check` 检查已审查的独立 FHD 模板。不要运行历史 720p 生成器覆盖新 RTL。

```powershell
python scripts/generate_fhd.py --check
python scripts/run_fhd_regression.py --workers 3
python scripts/run_fhd_build.py --stage full --timing-high --td "E:/TD 6.2.1/bin/td_commands_prompt.exe"
```

每次构建冻结实际输入并生成独立目录。最终建立/保持违例会在 bitgen 前拒绝；源输入发生变化也不得发布。回归报告含依赖哈希和夹具哈希，长联合视频采用带时间模型的 Verilator；采集、初始化、异常及代表性显示场景仍用 Icarus 做四态检查。两态仿真不能代替四态检查或板级测试。

本机已在 `tools/` 配置局部运行时，不修改系统 PATH。源码包保留运行时清单；迁移环境时按 [工具说明](docs/fhd_tools.md) 准备依赖。

已确认规格及四张本地任务单位于 `.scratch/native-1080p30/`。原始 720p 输入的审计保存在 `reports/baseline/`。
